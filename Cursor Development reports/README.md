# Cursor Development Reports

This folder contains all reports, documentation, and analysis files generated by Cursor AI during development.

## Purpose

All development reports, validation reports, analysis documents, and similar artifacts created by Cursor AI should be stored in this folder to keep the repository root clean and organized.

## Folder Structure

```
Cursor Development reports/
├── README.md (this file)
├── CONSTITUTIONAL_VALIDATION_REPORT.md
└── [future reports...]
```

## Report Naming Convention

Reports should follow this naming pattern:
- `[TYPE]_[DESCRIPTION]_[DATE].md` (e.g., `CONSTITUTIONAL_VALIDATION_REPORT.md`)
- Use `UPPER_SNAKE_CASE` for report filenames
- Include date in filename if multiple versions are expected

## Types of Reports

This folder may contain:
- **Validation Reports**: Constitutional compliance, architectural consistency
- **Analysis Reports**: Code quality, performance, security analysis
- **Documentation**: Generated documentation, API docs, summaries
- **Review Reports**: Code reviews, architectural reviews
- **Migration Reports**: Refactoring, migration, upgrade reports

## Rules for Cursor AI

When generating any report or documentation file:

1. **ALWAYS** save reports to `Cursor Development reports/` folder
2. **NEVER** create reports in the repository root
3. **USE** descriptive filenames with clear purpose
4. **INCLUDE** date/timestamp in filename if multiple versions expected
5. **UPDATE** this README if adding new report categories

## Examples

✅ **CORRECT:**
```
Cursor Development reports/CONSTITUTIONAL_VALIDATION_REPORT.md
Cursor Development reports/CODE_QUALITY_ANALYSIS_2025-01-15.md
Cursor Development reports/ARCHITECTURE_REVIEW_WEEK2.md
```

❌ **INCORRECT:**
```
CONSTITUTIONAL_VALIDATION_REPORT.md (root directory)
reports/validation.md (different folder name)
```
